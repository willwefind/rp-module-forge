## 1. 本轮目标与完成定义

在正式迁移后的产品上，依次完成档案与发布可靠性、论坛阅读体验、模块装配保存闭环。

最终验收主路径：

> 老乡找到一篇帖子 → 直接读到命中楼层 → 查看模块附件 → 到工坊按自己的身份调整 → 保存命名方案 → 刷新后恢复 → 导出配置。

同时必须保证：两个标签页编辑不会静默覆盖档案；未经验证的提交不能发布；浏览世界、读取帖子、套用附件不会擅自改变角色档案或权限。

本任务书是实施依据，不代表已经完成代码修改、测试或上线。任务编号用于追踪进度，不替代原有产品版本路线图。

## 3. 约束与不做项

- 继续以论坛为产品本体，Forge 是第一方工具；维持 Core / Pack / Web 边界。
- 保留现有主题正文、回复、署名、来源、缺页与冲突信息；不因美化改写档案内容。
- 继续使用唯一世界包档案源，不维护第二份主题 JSON 或复制出来的经验卡。
- 机器 ID `ancient-china` 不在本轮改名；未知身份、世界包、路线或不兼容配置不得猜测通过。
- 身份决定权限；路线、方案、附件、专家、导入文件均不能绕过派生与规范化校验。
- `notes` 不进入提示词、方案分享、Discussion 链接或公共诊断。档案备份已有的私密字段行为保持明确；不得把档案备份等同于公开分享。
- 真实社区仍使用 GitHub Discussions；不新增虚假活跃度、自动抓取真人投稿、自动授权或自动收录。
- 本轮不开发服务器、账号系统、数据库、AI 临场回帖、第二个正式世界包、SillyTavern Runtime、完整事件引擎、多语言或完整提示词导出。
- 不更换前端框架，不为拆文件进行全仓重写；不修改历史原型内容。
- 文档编写不自动授权提交、推送、合并或部署；实施交付时按当次用户授权执行。

## 5. 阶段 A：档案与发布可靠性

### R1. 多标签页档案并发保护

**发现**：论坛和工坊分别保有启动时读入的内存副本，保存时写回整柜；当前代码未见跨页更新监听或写入冲突检查。这是代码审查发现的覆盖风险，本次未修改真实档案做破坏性复现。

**入口**：`apps/web/src/profile/store.ts`、`src/forum/main.ts`、`src/forge/main.ts`、`apps/web/tests/profile.test.ts`。

**实现要求**：

- 将修改表达为具体操作：编辑某档案、删除、切换活动档案、导入；避免页面持有旧副本后直接覆盖整柜。
- 写入操作读取最新状态，校验预期修订，按操作合并。必要的存储版本升级应有迁移说明和旧版本 fixtures。
- 同源标签页监听外部更新。没有未保存输入时同步摘要；有编辑草稿时保留草稿并提示冲突，不替用户丢弃输入。
- 同一档案冲突提供“查看最新内容 / 保留本地草稿 / 核对后重新保存”，禁止静默最后写入获胜。
- 仅有 `storage` 事件或“读版本再写”不足以解决同时写入竞态。采用能串行化写事务的机制（如受支持环境中的 Web Locks），明确支持范围；不支持时使用可说明的保守回退，不声称已获得原子保护。
- 编辑、删除、活动档案切换、批量导入以及后续方案保存均经过统一写入入口。
- 保留损坏存储与写入受限时的恢复模式、可导出能力；保存失败后不能提示成功。

**验收**：

- [ ] A、B 两页先后编辑不同档案，两份修改均保留。
- [ ] A、B 编辑同一档案，B 的陈旧保存被识别，草稿不丢失。
- [ ] 同时提交两次修改也不会丢数据；测试覆盖互斥与回退路径。
- [ ] A 新建或删除后，B 切换活动档案不会复活旧数据或抹掉新档案。
- [ ] 导入覆盖与另一页编辑相遇时遵循相同冲突规则。
- [ ] v3/v4/v5 旧档案、待核对数据与私密备注保真；验证使用临时测试数据，不改真实档案。

## 6. 阶段 B：论坛阅读与视觉

### U1. 搜索命中、楼层直达与浏览器返回

**发现**：搜索“那盏灯后来还了”能命中永宁帝帖，打开后却从正文顶部开始；经验卡展示区域不跟随搜索；主题通过 `replaceState` 打开，未形成逐帖返回历史。

**入口**：`src/forum/model.ts`、`src/forum/main.ts`、`src/forum/forum.css`、`apps/web/tests/forum.test.ts`。

**实现要求**：

- 用结果对象表达命中来源、稳定主题/回复/经验卡 ID、摘要及匹配范围。索引由唯一档案源构造，不持久化另一份原文。
- 结果显示“正文命中 / 第 N 楼命中 / 经验卡命中”及短摘要；点击楼层结果时加载到该楼层、定位并突出关键词。
- 经验卡搜索覆盖经验内容、适用条件与失效条件；主题和经验卡分别显示准确命中数及空状态。
- URL 能表达公开的搜索、分区、主题、回复状态，不放入档案名、notes 或私人目标。可采用 hash / query 组合，维持 Pages 刷新兼容。
- 保留旧 `#topic=` 稳定 ID 与 V3 slug 链接；无效或畸形编码显示友好状态，不能导致页面崩溃。
- 定义返回语义：列表 → 帖子 A → 关联帖 B，返回到 A，再返回原列表与筛选位置；直接链接打开的主题关闭后回到站内列表。
- 高亮必须按文本节点或转义后的分段渲染，禁止把档案或搜索词当原始 HTML 注入。
- 正确恢复键盘焦点；定位目标有清楚的视觉与辅助技术提示。

**验收**：

- [ ] “那盏灯后来还了”直达永宁帝帖第 3 楼。
- [ ] 用第 5 楼之后的真实文本测试，自动加载到命中楼层，不要求反复点继续阅读。
- [ ] 标题、正文、作者、标签、回复、经验卡搜索及无结果均正确。
- [ ] 浏览器前进、返回、刷新、旧链接、未知 ID、畸形 hash 均有明确行为。
- [ ] 搜索与关闭长帖后保留原列表位置；正文和楼层原文无变化。

### U2. 导航减负与阅读模式

**入口**：`apps/web/index.html`、`src/forum/forum.css`、`src/theme.css`、`src/forum/main.ts`。

**实现要求**：

- 常驻区保留品牌/搜索、当前世界入口、主要栏目；未开放世界集中在“诸界图谱”，仍能查看说明并提交提案。
- 世界包只在相关世界上下文中展开；角色档案用简洁摘要入口表达。浏览世界不得改变活动角色。
- 手机避免多行并列横向导航；分区改为单一清楚的入口或可展开选择器。搜索不藏进多层菜单。
- 默认论坛首页至少展示一条完整主题；390×844 视口从顶部测量，首条主题顶部不晚于视口高度的 55%。长标题允许自然换行。
- 快速浏览保留抽屉；增加可切换完整阅读模式，包含字号调整、正文/楼层跳转。章节目录仅使用显式章节元数据，不靠猜测改写原文结构。
- 阅读位置按浏览器、稳定主题/回复 ID 保存，独立于角色档案；只定位仍存在的锚点，失效时安全回退。
- 延续纸白、夜档、青笺；整理字号、间距、按钮、表单、徽章规范。列表标题建议桌面 15–16px、手机至少 14px；必要元信息至少 12px，关键点击区域以 44×44px 为目标。
- 以排版和小标记区分求助、连载、模块、经验卡；审核状态不能仅靠颜色表达。
- 将机器编号与历史工程说明放在可展开来源区；适用性、缺页与来源性质仍可发现，不隐藏影响理解的事实。

**验收**：

- [ ] 390×844、768×1024、1440×900 三种尺寸；三主题均检查主页、搜索、长帖、档案对话框。
- [ ] 无页面级横向溢出、遮挡正文或无法操作的按钮；局部滚动有明确用途。
- [ ] 200% 缩放、键盘导航、Escape 关闭、焦点返回通过。
- [ ] 正文和关键标签达到 WCAG AA 对比度目标；检查真实颜色组合，不凭肉眼断言。
- [ ] 长帖刷新可继续读；不会把阅读进度写进角色 notes。
- [ ] 保存同视口前后对照截图，并记录未解决问题。

## 7. 阶段 C：装配方案与工坊闭环

### F1. 完整方案保存、恢复与导入导出

**入口**：`src/profile/`、`src/forge/main.ts`、`packages/core/src/canonicalNormalization.ts`、`packages/core/src/types.ts`。

**推荐模型**：角色档案保持“角色身份与人生路线”的职责；增加独立、可版本化的方案仓库，不直接把完整配置塞进 v5 档案。建议一个角色关联多个方案。

建议字段为 `schemaVersion`、`id`、`name`、可选 `profileId`、`config`、`revision`、创建/更新时间，以及可选公开附件来源 ID 与版本。`config` 复用 `CanonicalForgeConfig`，不建立平行配置契约。准确字段在实施时写入 schema 说明和测试。

**行为约定**：

- 保存覆盖能力模式、专家权重、论坛策略、运行设置、身份、路线、目标和本局补充；全部先规范化。
- 恢复方案只改变工坊草稿，不自动修改档案身份。与关联角色不一致时展示差异，由用户选择恢复方案原配置或按当前角色适配。
- “按当前角色适配”明确保留当前身份与路线，重新校验能力/专家兼容性，并展示变化；无法适配的部分不悄悄丢弃。
- 命名保存、另存为、重命名、覆盖和删除都有清楚的状态；覆盖/删除可撤销或明确确认。
- 刷新能恢复已保存方案；未保存修改有可见提示，离开或切换前提供保留草稿的明确路径。
- 方案导入与档案备份导入严格区分；支持当前 canonical manifest 和新方案格式，检查版本、世界包与稳定引用。未知版本不得覆盖现有方案。
- 方案导出不夹带角色 `notes`。`sessionPatch` 与自定义目标可能包含私人内容：本地备份可保存；对外分享副本默认排除，包含时显式选择并预览。
- 将导出的方案重新导入并规范化后，配置语义相等，权限仍由身份派生。
- 方案仓库沿用 R1 并发与恢复机制；关联档案被删除时保留方案并标记关联失效，不连带删除。

**验收**：

- [ ] 保存自定义能力与专家组合后刷新，完整恢复；切换另一个角色不会串档。
- [ ] 附件套用、恢复方案、另存为均不自动写回角色档案。
- [ ] 修改身份后明确显示与原方案/档案的差异，不能让方案赋予越权能力。
- [ ] 导入导出往返、重复 ID、未知版本、错误世界包、无效能力/专家均有测试。
- [ ] 导出方案与分享副本不存在角色 notes；私人本局补充的包含规则有测试。
- [ ] 多页冲突、存储损坏、配额不足和关联档案删除时不丢失原有数据。

### F2. 工坊三步操作与附件差异

- **第一步：确认角色**。显示当前身份、身份化路线和简短权限摘要；详细解释可展开。
- **第二步：调整方案**。能力、专家、论坛策略集中呈现；推荐项可解释“来自当前身份 / 当前路线”，手动修改有标记。
- **第三步：保存与输出**。方案名称、未保存状态、规范化结果、保存、另存为、现有三种输出放在容易到达的位置。
- 论坛摘录与维护日志移到可展开辅助区域，不夹在主要配置与输出之间；仍保留原来源入口。
- 来自模块帖时，保留帖子上下文，套用前展示新增/移除/改变的能力与专家，明确是否替换现有选择。
- “写回档案”明确命名为身份与路线写回，与“保存装配方案”区分。两者作用域及失败状态不能混淆。
- 信息密度与按需能力的界面说明保持实现诚实，不能把配置字段描述成已经存在的运行时效果。

**验收**：

- [ ] 从皇帝模块帖进入工坊，以奴婢当前身份核对、调整、保存；身份与权限没有被附件改变。
- [ ] 首屏可识别当前角色、当前方案状态及下一步入口；手机不需翻过维护日志才能保存或导出。
- [ ] 推荐解释与现有 resolver 一致；恢复推荐前明确会覆盖手动选择。
- [ ] 未保存、保存成功、保存失败、待核对四种状态可区分，键盘可完成完整流程。

## 8. 随任务进行的架构整理

- `forum/main.ts` 逐步分离搜索、URL 状态、主题阅读、档案 UI 和社区入口；入口只负责组合与启动。
- `forge/main.ts` 逐步分离配置状态、推荐解析、附件处理、方案保存和输出；从同一状态生成 UI 与导出结果。
- DOM 渲染与纯数据处理分开，统一转义边界；不重复实现 Core 校验。
- 世界包加载收口到一个注册入口，统一提供 pack、archive、导航与 profile catalog；本轮只注册已开放的架空王朝。
- `threadById`、`replyById`、检索文本等按当前档案建立一次索引，避免每次输入反复全量构造 Map。40 帖规模不引入复杂搜索服务。
- CSS 保持可阅读的分段规则，提取共享样式规范；不维护新的原型 CSS 副本。
- 拆分必须服务于当前任务或回归测试，避免单独开展无边界的重构。
