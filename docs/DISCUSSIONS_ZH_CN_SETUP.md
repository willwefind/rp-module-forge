现阶段不要按“架空王朝 / 武侠 / 修仙 / 星际……”给真人社区各建一个分类。先用标题、表单字段和内容本身标世界；真实流量证明需要拆分时再拆。

## 已接通的 Discussion forms

GitHub 要求 Discussion form 文件名与 category slug 对应。当前仓库已有：

```text
.github/DISCUSSION_TEMPLATE/
├── 天道公告.yml
├── 反馈与点子.yml
├── rp-实战回报.yml
├── 模块投稿.yml
├── 世界包提案.yml
├── 经验复现与勘误.yml
└── 求助与问答.yml
```

这些表单不是七份相同模板：

- **RP 实战回报**：世界域 / 世界包、身份、路线、具体事件、有效与翻车部分、留给后来者的话；
- **世界包提案**：Realm、Pack 名称、核心体验、身份 / 权力 / 资源规则，以及为什么它应当是独立 World Pack；
- **反馈与点子**：反馈类型、影响页面、实际表现、预期表现、环境；
- **天道公告**：公告类型、影响范围、正文、用户需要做什么、相关记录；
- **模块投稿**：目标世界、适用身份 / 路线、能力 / 专家组合、权限与误用风险、现有材料；
- **求助与问答**：问题类别、问题本体、已经尝试的东西、相关页面；
- **经验复现与勘误**：来源档案、复现 / 反例类型、世界 / 身份 / 路线背景、过程、建议修正和证据。

公开投稿类表单还会询问：

- 是否愿意未来被整理进产品论坛 / FAQ / 模块仓；
- 论坛署名方式：预设、随机编号、自定义署名或 GitHub 用户名；
- 自定义署名；
- 是否允许尽量保留原文语气（适用类别）；
- 公开 GitHub 来源与 provenance 确认。

## 署名与导入边界

表单只收集**偏好与授权意向**，不会自动完成产品论坛导入。

真实路径仍然是：

```text
GitHub Discussion
→ 保留真实来源与 GitHub attribution
→ 检查署名 / 授权 / 隐私
→ 维护组 review
→ 可选导入产品论坛
→ 若存在可复用知识，再单独 review 进入【老乡经验库】
```

自定义署名允许存在，但需要轻量审核；预设随机编号只是候选显示身份，长期连续身份以后再由 contributor registry 解决。

## 手动管理分类的位置

以后如果要改分类标题、emoji、说明或格式：

```text
仓库 → Discussions
→ 左侧 Categories 旁的编辑入口
→ 新建 / 编辑分类
```

分类 slug 一旦变化，对应 `.github/DISCUSSION_TEMPLATE/<slug>.yml` 文件名也必须同步调整，否则表单不会继续绑定该分类。

## 数据与成本边界

GitHub Discussions 继续承担 Phase 1 的真实账号、发帖、回复、reaction 与基础审核层。产品论坛和 RP 本局档案仍不需要自建账号服务器或付费数据库。

真实 Discussion 始终是来源记录；表单提交不会自动把内容放进【老乡经验库】，reaction 热度也不会自动提升可靠度。
